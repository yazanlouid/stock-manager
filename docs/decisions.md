## Open (needs a call)

The simulator runs in time order, so only API clients can do this. Decide alongside week 2's counts.

| D36 | 2026-11-10 | Task 4 details. Every receive creates the default batch of each item it touches. The default batch row is that item's lock at a location: receive, use, waste and reverse lock it first, then load the other batches in a second statement, because under READ COMMITTED a single SELECT … FOR UPDATE that waits keeps its old snapshot and misses batches a concurrent receipt inserted. Default batches are created with INSERT … ON CONFLICT, and every new batch gets its balance row. A retry with the same client_id writes nothing and returns what was written; reusing a client_id for another kind of request is an error. A reversal copies its original's unit_cost and occurred_at. last_movement_at is the latest occurred_at. Rule breaks raise one DomainError (a ValueError subclass). Blank invoice_ref and lot_code become NULL; timestamps without a timezone are refused; unit costs round half-up to six decimals; a qty_base that needs more than three decimals is rejected. | Active |
